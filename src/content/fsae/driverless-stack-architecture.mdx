## The plan

- **Retrofit the existing FSAE Electric car.** Every team that reached a
  driverless competition in under a year started from a running EV.
- **Target FSAE 2028**, two years ahead of SAE's 2030 mandate.
- **Build order: acceleration, autocross, trackdrive, skidpad.** 150 of the
  250 dynamic points are speed-independent, so reliability outranks pace.
- **Compute on the NVIDIA Jetson Orin**, with one C++/ROS 2 monorepo:
  packages grouped by pipeline stage, one shared interface package, colcon and
  Docker. Closest references are AMZ's `fsd_skeleton` and QUT's
  `QUTMS_Driverless`.
- **Budget of $28,234 CAD** across 56 line items, $18,233 of it rules-critical.
  The Gross-Funk remote emergency system is the longest lead item, so it gets
  ordered first regardless of what else is settled.

</Step>

## Repository layout

The structure the planning repo recommends for the monorepo, synthesised from
QUT (layout), AMZ (layering) and CMU (dev environment). Packages are grouped by
pipeline stage, `umsae_msgs` is the one interface package everything else
depends on, and the simulator adapter can be excluded from car builds.

</Step>

```text
umsae-driverless/                      # one repo = one colcon workspace
├── README.md                          # what/why, quickstart, links to docs/
├── LICENSE
├── .gitignore                         # build/ install/ log/ bags/ *.engine ...
├── .gitmodules                        # external ROS packages as submodules
├── .clang-format                      # C++ style (pick one, never argue again)

│   ├── docker-compose.yml             # dev, sim, (optional) ml profiles
│   ├── cyclonedds.xml                 # pinned DDS config
│   └── Makefile                       # make dev / make sim / make build

├── docs/
│   ├── onboarding.md                  # zero-to-running-sim guide (test on a fresh laptop)

│   │
│   ├── estimation/                    # (QUT folds this into "navigation")
│   │   ├── state_estimation/          # wheel odom + IMU + GNSS fusion (try robot_localization first)

│   │   └── estimation_bringup/
│   │
│   ├── planning/

│   │   └── actuation/                 # steering/brake/throttle interfaces, EBS state machine
│   │
│   ├── operations/

│   │   │                              #   autocross, trackdrive, inspection

│   │   └── recording/                 # rosbag recorder + topics_to_record.yaml
│   │
│   └── sim/
│       └── sim_interface/             # adapter to eufs_sim/FSDS; excluded from car builds
│
└── tools/                             # non-ROS: CLI helpers, dataset scripts,
                                       #   Foxglove layouts, track generators
```
